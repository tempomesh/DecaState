How it works · the honest version

The model never decides to skip old work.
The runtime does.

This is the whole idea, and almost everyone gets it wrong. A model has no memory that it already read your repository. Something outside the model — a KV cache — decides to reuse the work instead of redoing it. DecaState is that decision made explicit, and measured.

The baseline · no cache

Without a cache, every request redoes everything

Two questions about the same repository. With no cache, the GPU (or the provider) processes the entire repository twice — the model doesn't remember it already did.

[system + repository + question 1]

The fix · KV cache

With a KV cache, the stable prefix is reused

Request 1 saves the K/V state (the model's attention state for the repository). Request 2 reuses it and only processes the new question. The model still uses the old context — it just doesn't rebuild the old K/V tensors.

A common misconception

The cache is not the answer

The KV cache holds numerical attention state — "what the model has already processed" — not a saved final answer. Ask the same question twice and prompt caching still generates a fresh response; only a separate response cache would return the old answer.

KV cache = old attention state, reused  ≠  saved answer
old K/V + new question → attention → new reasoning → new answer
What "token cost" means

A token is both a unit of processing and a unit of billing

API providers separate the bill into parts. DecaState's audit reads every part from the provider's own reported usage — nothing estimated.

input · what you send cached input · old input reused (cheaper) output · what the model generates reasoning · internal tokens (some models) tool · files, search, commands
# total API cost =
  input-token cost
 + cached-input cost  ← where caching saves
 + output-token cost
 + reasoning / tool charges when applicable
Where the saving actually happens

Different layer, different currency

LOCAL MODEL

  • GPU skips old-prompt prefill
  • computes only the new continuation
Saves GPU compute · time · electricity · latency. Not an API bill — the model runs on your machine. This is where DecaState saves & restores the actual local K/V state.

API MODEL

  • old input billed at cheaper cached rate
  • provider still runs inference, still bills output
Saves API input cost only. DecaState's job here is to measure the provider's cache — and, for clients that don't cache, help activate it. It never touches the provider's tensors.
The honest summary
The model does not say:
"I already know this, so I'll do nothing."
The runtime says:
"I have the attention state for this prefix,
so I'll reuse it instead of rebuilding it."
DecaState's local contribution is saving and restoring the real K/V state. Its API contribution is measuring — and helping activate — provider-native prompt caching. Every number we show is provider-reported or reproducible from the repo.
