LOCAL MLX · Q / K / V

How the cache carries the conversation

✓ local state explained

The model reads the first prompt and creates attention state. DecaState saves the Keys and Values. Each later prompt creates a new Query, reads the earlier K/V state, and appends its own K/V state.

Q · QueryWhat the current token is looking for.
K · KeySignals describing earlier tokens.
V · ValueInformation carried by earlier tokens.

WHY “PROCESS DEATH” MATTERS

Process A reads the prompt, saves K/V, and exits. Its RAM and PID disappear. Process B starts separately, validates the fingerprint, loads the file, and continues. The original prompt is not prefetched again.

WEIGHTS → K/V → STORAGE
MODEL WEIGHTS = permanent learned numbers
KV CACHE      = temporary numbers for this processed conversation

Local MLX:    weights + tokenizer → MLX/Apple GPU → K/V → DecaState file
API model:    your prompt → internet → provider weights/GPU → provider K/V
              DecaState sees usage fields, not the provider's private tensors
